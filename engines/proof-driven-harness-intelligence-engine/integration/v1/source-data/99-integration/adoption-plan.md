# Adoption Plan

## Phase A — Contracts first

Implement:
- canonical schemas;
- authority ladder;
- evidence ids/provenance;
- strict structured outputs;
- common failure taxonomy.

Exit:
All existing Elmos core workflows can emit `AgentTask`, `PatchTransaction`, `EvidenceRecord`, and `CertificationBundle` skeletons.

## Phase B — Semantic mutation core

Implement:
- LSP federation;
- semantic graph;
- semantic anchors;
- AST/IR rewrite router;
- transaction rollback.

Exit:
Spring modernization and one cross-language Golden Route complete edits without unanchored broad replace.

## Phase C — Isolated multi-agent

Implement:
- workspaces;
- owner/lease/fence;
- typed yields;
- task DAG;
- merge verifier.

Exit:
Concurrent workers cannot overwrite siblings or merge stale results.

## Phase D — Runtime proof

Implement:
- DAP abstraction;
- scenario traces;
- source/target differential comparison;
- replay;
- counterexample-guided repair.

Exit:
At least one Golden Route has E3 evidence automatically generated.

## Phase E — Assurance / invariant plane

Implement:
- independent advisors;
- watchdog roles;
- RuleIR;
- JIT semantic guard;
- certification findings.

Exit:
Known-danger transformations are blocked before merge and emit evidence.

## Phase F — Durable commercial runtime

Implement:
- restart-safe job state;
- idempotent tool effects;
- cost/token/revenue metering;
- ETA;
- audit;
- operator controls.

Exit:
Kill/restart server during large job without duplicated side effects or lost committed progress.

## Phase G — Skill evolution

Implement:
- failure/repair memory;
- lesson extraction;
- fixture generation;
- regression corpus;
- certification/promotion.

Exit:
New production skills can only enter via automated gated lifecycle.
