# 内部流程：质量、性能与安全验收

输入：baseline/candidate、预声明主目标和guardrails、固定数据/环境/模型/策略digest、待发布scope。

1. 冻结协议和质量标签；覆盖exact/语义/图谱/跨语言/SQL/诊断/无答案及安全案例。
2. 按repo家族拆分开发、调优、holdout，防泄漏；同case成对交错执行，分冷暖和并发。
3. 分别验证引用存在、字节真实、结论支持，不能仅统计引用数量。
4. 计算Recall/MRR/nDCG、业务通过、拒答、p50/p95、全部尝试Token/计算成本；保留失败超时和未完成项。
5. 无答案单列；重复次数不能代替独立样本数。按语言/规模/权限选择性分层，报告repo聚类区间。
6. 质量不劣、主目标改善、latency/cost预算与安全0违规同时满足，才考虑灰度。不得事后调阈值。
7. 注入撤权、旧index/worker、unknown结果、模型/搜索超时、取消和日志污染故障。
8. 实际消费者E2E、旧客户端兼容、flag/index/graph回滚；不删除已发生动作或其证据。
9. 包测试与产品测试分别报告，native backend缺失必须not_run，不用double代替。
10. release_gate只做本地完整性检查；最终host验签/语义审核/K8裁决。

交付：原始日志/成本、版本与环境、实际命令、分层对照结果、已知不足、qualifed scope和可撤销批准引用。
