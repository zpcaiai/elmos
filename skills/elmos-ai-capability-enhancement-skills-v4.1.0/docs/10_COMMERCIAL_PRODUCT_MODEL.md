# Commercial Product Model

## Product editions

### Developer

- local/import/generate for selected targets;
- repository CLI and SDK;
- basic RAG and agent evals;
- single user/project;
- no production certificate.

### Team

- shared projects, Git integrations and CI;
- durable runs, approvals and trace;
- usage credits and budgets;
- selected P0 adapters;
- bounded E0–E4 reports.

### Enterprise

- SSO/SCIM, tenant/RLS/audit;
- customer VPC/private runners and models;
- provider/data residency policy;
- signed adapters and release artifacts;
- E0–E5/P05 evidence and certification;
- support/compatibility SLAs;
- Golden Route services.

### OEM/Platform

- white-label API/control plane;
- custom target adapters and Domain Packs;
- private registry and policy bundles;
- evidence/certificate integration;
- commercial license and support.

## Billable units

The ledger can support:

- input/output/cached tokens;
- model/provider surcharge;
- sandbox/runner seconds;
- verifier compute;
- storage/evidence retention;
- document/index operations;
- target generator/adaptor tier;
- concurrent run capacity;
- customer VPC/private runner;
- certification and Golden Route service;
- support/upgrade subscription.

Prepaid credit and per-project pricing can coexist. Quotes must separate machine cost, platform margin, optional human review and external provider charges.

## Value propositions

1. **One semantic source, multiple targets.**
2. **Visual prototype without production lock-in.**
3. **Repository-scale generation, not snippet scaffolding.**
4. **Durable, governed side-effecting agents.**
5. **Independent evidence rather than “agent says done”.**
6. **Migration and upgrade paths across fast-changing AI ecosystems.**
7. **Java/Spring and enterprise operations as first-class targets.**
8. **Machine wall-clock ETA, cost and risk transparency.**

## Commercial claims hierarchy

| Claim | Minimum evidence |
|---|---|
| Supports target format | schema/fixture parse |
| Generates target project | emitted repository + deterministic manifest |
| Target-native compatible | official import/build/load at exact version |
| Production-capable | E0–E5/P05 for declared envelope |
| Behavior-equivalent migration | differential/property/side-effect evidence |
| Commercial Golden Route | repeated independent runs + holdout + customer acceptance |
| Certified | signed K8 certificate bound to exact evidence root |

Marketing and UI must use the same hierarchy.

## Adapter support policy

Each release publishes:

- supported exact versions;
- conditional features and limitations;
- compatibility window;
- deprecation dates;
- known critical defects;
- upgrade path;
- security advisories;
- native conformance result;
- certificate/evidence scope.

“Latest” cannot be a release promise without a conformance run.

## Customer onboarding

1. Data and repository classification.
2. Source/target eligibility and licensing.
3. Identity, network, secret and provider policy.
4. Acceptance/assurance level.
5. Budget and machine ETA envelope.
6. Pilot vertical slice.
7. Security and operations review.
8. Golden Route qualification.
9. Production cutover and rollback rehearsal.
10. Ongoing drift/recertification.

## Enterprise boundaries

- Customer code/data are not used to train/promote rules without explicit contract and sanitization.
- Cross-customer evidence and caches are isolated.
- A waived risk has an owner, reason, expiry and visible certificate impact.
- Human reviewers cannot override immutable negative evidence; they can revise the Goal/assumptions or authorize a bounded waiver under policy.
- Third-party framework support is limited by upstream licenses, APIs and versions.
- Legal, privacy and sector regulation require jurisdiction/customer-specific review.

## Moat

The defensible assets are not the templates alone:

- AI-SIR and semantic profiles;
- target capability/evolution corpus;
- import/lowering rules;
- normalized traces and differential oracles;
- failure/counterexample corpus;
- repository and AI project benchmarks;
- signed adapter conformance history;
- Golden Route evidence;
- cost/ETA models;
- customer-specific Domain Packs and assurance policies.
