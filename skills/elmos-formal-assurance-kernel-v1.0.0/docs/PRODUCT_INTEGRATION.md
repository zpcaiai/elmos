# Product Integration

## User journey

1. Elmos inventories a repository/request and presents the formalization scope.
2. The user sees unresolved P0 ambiguities and assumptions before execution.
3. The plan shows proof methods, expected machine ETA, credit reservation and allowed bounds.
4. Progress displays each obligation without merging unknown/bounded/proved.
5. Counterexamples open as source-linked replayable tests.
6. Completion shows engineering detail, executive summary and release impact.
7. Drift automatically changes current assurance and explains the minimal reproof set.

## Commercial packaging

Formal assurance can be sold as:

- per-project certification;
- premium Golden Route;
- continuous assurance subscription;
- regulated/private-deployment package;
- proof evidence/audit bundle;
- formal rule/profile development.

Billing is based on actual reserved/consumed credits and infrastructure, not an unsupported guarantee of proof completion. Unknown results still consume computation but are reported transparently.

## Roles

Developer authors/fixes code; domain owner approves specification; formal engineer reviews models; security owner approves security assumptions; business owner accepts residual business risk; release manager evaluates gates; auditor reads immutable evidence.
