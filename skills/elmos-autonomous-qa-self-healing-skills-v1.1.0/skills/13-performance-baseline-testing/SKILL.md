# Performance Baseline Testing

## 目标

建立可比较的性能基线、负载模型和 SLO 预算，检测延迟、吞吐、错误率和资源消耗回退。

## 何时调用

当工作流进入 `13-performance-baseline-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 业务流量模型、并发、数据规模和关键场景
- SLO/性能预算或 provisional 目标
- 可控环境、监控指标和基线版本

## 输出契约

- 性能测试脚本、环境校准和基线结果
- p50/p95/p99、吞吐、错误率和资源曲线
- 与批准基线的差异及置信区间

## 执行步骤

1. 把业务旅程转换为到达率、并发、数据和 think-time 模型。
2. 预热系统并验证环境噪声、数据缓存和监控完整性。
3. 运行稳态基线，采集客户端与服务端指标/trace。
4. 比较当前版本与同环境批准基线。
5. 关联慢请求、数据库、缓存、GC/内存、CPU、网络和外部依赖。
6. 保存脚本、环境镜像、数据版本和结果哈希。

## 不可违反的控制

- 性能结论不得跨不同环境直接比较。
- 平均值不能替代尾延迟。
- 错误请求不得从延迟统计中静默排除。
- 负载生成器自身饱和时结果无效。

## 完成判定

- 关键场景有可重复基线。
- 报告包含分位数、吞吐、错误率和饱和指标。
- 超过批准回退阈值时门禁失败。
- 环境和负载模型足以重放。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。
