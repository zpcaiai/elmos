# Message & Workflow Testing

## 目标

验证消息、事件、定时任务、长事务、Saga 和异步工作流的顺序、重复、丢失、补偿与恢复。

## 何时调用

当工作流进入 `09-message-workflow-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 消息 Schema、topic/queue、生产者/消费者和路由
- 重试、死信、顺序、交付语义和幂等规则
- 工作流定义、超时、补偿和状态存储

## 输出契约

- 异步测试、故障注入计划和消息证据
- 重复/乱序/延迟/丢失/毒消息缺陷
- 工作流状态迁移与补偿报告

## 执行步骤

1. 验证 Schema、版本兼容、必填字段和未知字段处理。
2. 注入重复、乱序、延迟、丢失和消费失败。
3. 检查业务幂等、去重窗口和副作用恰好一次语义。
4. 验证重试上限、退避、死信、重放和人工恢复。
5. 对 Saga 执行每个步骤失败并验证补偿。
6. 对定时任务验证时区、夏令时、重复触发和漏触发。

## 不可违反的控制

- 不得以 broker ack 代替业务处理成功。
- 消息重放必须使用隔离账户/命名空间。
- 补偿动作自身也必须幂等。
- 事件时间与处理时间要区分。

## 完成判定

- 至少一次交付下无重复业务副作用。
- 毒消息不会阻塞整个分区或队列。
- 所有失败点有可验证恢复路径。
- 消息证据可按 correlation_id 重放。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
