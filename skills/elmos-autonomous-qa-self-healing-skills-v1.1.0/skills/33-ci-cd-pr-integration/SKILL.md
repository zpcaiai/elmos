# CI/CD & Pull Request Integration

## 目标

把自主 QA 接入 PR、主干、夜间和发布流程，提供不可伪造的状态检查与证据链接。

## 何时调用

当工作流进入 `33-ci-cd-pr-integration` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- Git 提交/PR、变更集、代码所有权和分支策略
- CI 事件、质量门禁和执行 profile
- QA Control Plane API 与证书验证器

## 输出契约

- PR 状态检查、评论摘要和证据链接
- 增量测试、夜间全量和发布认证任务
- 合并阻断、审批和发布证书

## 执行步骤

1. PR 创建/更新时生成新快照和影响范围。
2. 运行变化相关测试、P0 固定套件和变更契约/安全测试。
3. 影响置信度低时自动升级为全量 Required。
4. 把失败、阻塞、Flaky、覆盖缺口和修复候选回写 PR。
5. 主干/夜间执行全量与趋势；发布候选执行认证工作流。
6. 验证状态来源、证据哈希和候选提交一致。

## 不可违反的控制

- PR 作者不能伪造 QA 状态或替换证据链接。
- 质量门禁文件变更需独立审批。
- 缓存只能复用输入哈希完全匹配的结果。
- 自动修复 PR 与原功能 PR 变更必须清晰区分。

## 完成判定

- 合并按钮受真实门禁结果控制。
- 提交变化自动使旧结果失效。
- 失败可从 PR 直接进入复现证据。
- 发布只接受对应提交的有效证书。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
