# Visual & Responsive Testing

## 目标

发现布局错位、样式回退、字体溢出、主题、本地化和响应式断点问题，并管理可信视觉基线。

## 何时调用

当工作流进入 `11-visual-responsive-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 组件/页面视觉基线、设计 token 和允许差异规则
- 视口、DPR、主题、语言和内容长度矩阵
- 稳定字体、浏览器和渲染环境

## 输出契约

- 视觉快照、像素/结构差异和分类
- 响应式布局、溢出、遮挡和可读性缺陷
- 基线更新申请与审批记录

## 执行步骤

1. 固定字体、时区、动画、随机数据和浏览器版本。
2. 为关键组件和页面生成多视口、多主题、多语言快照。
3. 同时做像素差异和布局语义检测，降低抗锯齿噪声。
4. 识别截断、重叠、不可点击、横向滚动和层级异常。
5. 将差异分类为预期、环境噪声或真实缺陷。
6. 视觉基线只在明确需求/设计变更且审批后更新。

## 不可违反的控制

- 禁止失败后自动无条件接受新基线。
- 全局阈值不得掩盖局部关键差异。
- 动态区域必须使用语义 mask 并记录原因。
- 基线与代码提交、浏览器镜像和字体清单绑定。

## 完成判定

- 所有关键页面覆盖声明断点和主题。
- 无未解释视觉差异进入发布。
- 基线更新可追溯到需求/设计变更。
- 视觉失败可在固定环境稳定重现。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
