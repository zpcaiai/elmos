# QA Control Plane

## 目标

提供自主测试任务的统一控制面、持久化状态机、预算、权限、审批和审计，使长时间测试与修复任务可创建、观察、暂停、恢复、取消和重放。

## 何时调用

当工作流进入 `00-qa-control-plane` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 项目 ID、快照引用和执行模式
- 测试范围、质量门禁、资源/时间/修复预算
- 调用者身份、租户、权限和幂等键

## 输出契约

- QaRun 与不可变创建事件
- 阶段状态、进度、ETA、预算消耗和阻塞原因
- 控制命令结果、审批记录和审计轨迹

## 执行步骤

1. 校验调用者、项目、模式和策略组合；拒绝无权或高风险配置。
2. 以幂等键创建 QaRun，写入事件日志并分配稳定 run_id。
3. 驱动状态机，只允许显式合法迁移；每次迁移保存检查点。
4. 向工作流调度器发布阶段命令，接收 Worker 心跳和分片提交。
5. 在 pause/cancel 时等待安全点，冻结新副作用并执行必要补偿。
6. 聚合状态、证据、缺陷、补丁、门禁和 ETA，向 CLI/API/事件流提供一致视图。

## 不可违反的控制

- 不得以数据库字段直接修改代替状态机命令。
- 重复 create/resume/cancel 不得产生重复任务或重复副作用。
- 客户端断线不得自动取消服务端任务。
- 所有策略变更、审批和人工覆盖必须留痕。

## 完成判定

- 编排服务重启后可从事件日志恢复同一 run。
- 并发重复命令只能有一个有效结果。
- 非法状态迁移被拒绝并产生审计事件。
- 控制面不可访问生产凭据或直接执行测试代码。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## v1.1.0 项目产出控制面

- Run 状态机必须包含 `materializing_test_artifacts` 和 `publishing_output`。
- 控制面管理 ProjectOutput、Bundle 发布、下载权限、幂等键和失败后的 partial 产出。
- 非 `plan-only` Run 没有 output_ref 时不能进入成功终态。
