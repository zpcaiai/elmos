# Test Oracle & Evidence Engine

## 目标

执行多维测试 Oracle 并生成可验证、可脱敏、可重放的证据链。

## 何时调用

当工作流进入 `20-test-oracle-evidence` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- TestCase Oracle、需求不变量和契约
- 运行日志、返回值、数据库、消息、UI、metric 与 trace
- 证据策略、保留和脱敏规则

## 输出契约

- Oracle 判定、失败差异和置信度
- EvidenceArtifact 与签名 manifest
- 重放命令、环境引用和完整性哈希

## 执行步骤

1. 在执行前验证 Oracle 来源和容差依据。
2. 采集客户端、服务端、数据、消息和 UI 多源观察。
3. 按业务语义评估值、状态、事件、时序、资源、视觉和差分断言。
4. 最小化失败差异并关联具体步骤/需求。
5. 对秘密和个人数据脱敏，失败则隔离证据。
6. 生成哈希清单并在认证时签名。

## 不可违反的控制

- 不可仅以退出码、HTTP 200 或元素存在作为关键测试 Oracle。
- 证据脱敏失败时不得发布。
- 同一证据对象不可被后续运行原地覆盖。
- Verifier 必须可独立重算关键 Oracle。

## 完成判定

- 每个结果至少有一个可定位证据。
- 报告数字可回溯到证据或查询。
- 证据哈希校验通过且可重放。
- 关键业务副作用得到跨层验证。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
