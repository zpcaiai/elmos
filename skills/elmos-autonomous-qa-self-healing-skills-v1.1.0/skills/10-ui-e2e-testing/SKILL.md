# UI End-to-End Testing

## 目标

在真实浏览器/设备环境中验证关键用户旅程、交互、权限、网络和错误状态。

## 何时调用

当工作流进入 `10-ui-e2e-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- UI 路由、组件树、设计说明和用户旅程
- 角色/租户、浏览器/设备支持矩阵
- 后端 API、测试账户和数据夹具

## 输出契约

- 稳定的 UI E2E 测试与页面对象/组件模型
- 截图、视频、DOM、控制台、网络和 trace 证据
- 关键流程通过率与失败复现脚本

## 执行步骤

1. 从 UXR/AC 生成关键旅程和每步可观察结果。
2. 优先使用可访问性角色、标签和稳定测试 ID 定位。
3. 覆盖表单、导航、上传下载、刷新、后退、错误和会话过期。
4. 注入弱网、超时、服务错误和离线，验证用户可恢复性。
5. 检查控制台错误、失败请求、未处理异常和意外跳转。
6. 在声明支持的浏览器/设备矩阵执行并隔离测试数据。

## 不可违反的控制

- 禁止使用脆弱的绝对 XPath 作为默认 locator。
- 不得用固定 sleep 代替可观察等待。
- UI 成功必须验证后端/数据副作用。
- 自动更新 locator 不得改变业务语义或跳过步骤。

## 完成判定

- 所有关键用户旅程在支持矩阵中通过。
- 失败包含视频/截图/trace/网络证据。
- 测试可独立、并行、重复运行。
- 无未解释的控制台错误和资源加载失败。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
