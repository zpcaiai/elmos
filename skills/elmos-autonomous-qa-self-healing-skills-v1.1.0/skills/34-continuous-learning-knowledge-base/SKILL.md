# Continuous Learning Knowledge Base

## 目标

从历史需求、测试、缺陷、补丁、波动、性能和误报中沉淀可版本化规则，提高后续生成、定位和 ETA 准确性。

## 何时调用

当工作流进入 `34-continuous-learning-knowledge-base` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 经过认证的 Run、缺陷、补丁和证据
- 人工审批/拒绝、误报和根因标签
- 测试强度、性能趋势和 ETA 误差

## 输出契约

- 版本化测试模式、修复模式、风险规则和耗时模型
- 适用范围、置信度、来源和回滚版本
- 离线评估与上线批准记录

## 执行步骤

1. 仅从有证据和最终结论的数据提取候选知识。
2. 区分项目专用、框架专用和通用规则。
3. 在历史快照离线回放，比较缺陷发现率、误报和成本。
4. 使用对照组验证规则不会降低覆盖或安全。
5. 审批后小范围启用，监控漂移并可回滚。
6. 记录知识对每个决策的具体贡献。

## 不可违反的控制

- 未经评估的自动学习不得直接改变生产门禁。
- 项目私有数据不得跨租户泄露。
- 错误补丁和未确认根因不能作为正样本。
- 知识删除/降权也要保留审计。

## 完成判定

- 每条规则有来源、版本、范围和评估指标。
- 上线规则可回滚。
- 跨租户隔离测试通过。
- 生成质量或 ETA 精度改进可量化。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## v1.1.0 测试资产学习

- 沉淀“需求模式 → 测试文件模板 → 发现/构建成功率 → 缺陷发现效果”，但新模板必须离线回放后才能启用。
- 学习库引用内容哈希和版本，不直接覆盖已认证项目产出。
