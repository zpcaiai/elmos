# Impact Analysis & Regression

## 目标

根据追踪图、调用图、依赖和运行数据选择影响回归，并在任何产品补丁后执行全量 Required 回归。

## 何时调用

当工作流进入 `26-impact-analysis-regression` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- Patch diff、代码/数据/事件调用关系
- 追踪图、覆盖映射和历史失败
- 测试耗时、环境与资源预算

## 输出契约

- 受影响需求、组件和测试集合及置信度
- 影响回归与全量回归结果
- 未覆盖影响、回退和新缺陷报告

## 执行步骤

1. 解析符号、配置、Schema、依赖和数据库变化。
2. 沿调用、数据、事件和契约边传播影响。
3. 加入同模块历史缺陷、P0 安全边界和变异幸存区域。
4. 先运行原失败和影响测试，快速淘汰错误补丁。
5. 产品代码补丁通过后运行全量 Required 套件。
6. 比较基线，检查性能、视觉、安全和覆盖回退。

## 不可违反的控制

- 影响分析置信度低时必须扩大到全量。
- 全量回归不得因时间预算自动取消而报告通过。
- 新增失败必须作为新缺陷处理。
- 测试选择逻辑和输入需可审计。

## 完成判定

- 影响集合包含直接和传递依赖。
- 所有产品补丁有全量回归证据。
- 无回归失败、覆盖下降或未解释基线漂移。
- 选择置信度和回退条件明确。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
