# Accessibility & Compatibility Testing

## 目标

验证键盘、焦点、语义、标签、对比度和跨浏览器/设备兼容性，确保关键流程可被不同用户和终端使用。

## 何时调用

当工作流进入 `12-accessibility-compatibility-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 可访问性目标、支持浏览器/设备/OS 矩阵
- DOM、ARIA、设计 token、键盘交互和本地化
- 关键用户旅程

## 输出契约

- 自动规则扫描与人工可观察检查脚本
- 键盘顺序、焦点陷阱、标签、对比度和语义缺陷
- 兼容性矩阵与降级行为报告

## 执行步骤

1. 扫描结构、名称、角色、状态、对比度和表单关联。
2. 执行仅键盘的关键旅程，验证焦点可见、顺序与恢复。
3. 验证弹窗、菜单、表格、错误提示和动态更新语义。
4. 在支持浏览器/设备运行关键流程和能力探测。
5. 检查不支持能力时的明确降级与用户提示。
6. 将自动规则与旅程级语义验证合并，避免只做扫描。

## 不可违反的控制

- 自动扫描通过不代表可访问性整体通过。
- 关键流程中的严重违规不可豁免为低优先级。
- 浏览器 UA 模拟不能完全替代真实引擎验证。
- 可访问性修复不得破坏视觉或交互。

## 完成判定

- 关键流程无 Critical 可访问性违规。
- 键盘可完成登录、核心业务和退出/恢复。
- 所有声明支持终端有执行证据。
- 兼容性例外具有明确降级与文档。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
