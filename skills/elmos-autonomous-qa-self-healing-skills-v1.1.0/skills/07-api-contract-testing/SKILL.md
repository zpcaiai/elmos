# API & Contract Testing

## 目标

验证 REST、GraphQL、gRPC/Proto 和服务间消费者契约的结构与行为兼容性。

## 何时调用

当工作流进入 `07-api-contract-testing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- OpenAPI/GraphQL/Proto/AsyncAPI 等 Schema
- 消费者契约、版本策略、鉴权和错误规范
- API 实现与依赖模拟/真实端点

## 输出契约

- Schema 校验、行为契约和兼容性测试
- 破坏性变更报告、消费者影响列表
- 请求/响应、trace、HAR 和服务端副作用证据

## 执行步骤

1. 解析操作、字段、类型、约束、错误和安全方案。
2. 生成合法、非法、缺失、额外、极值和内容类型测试。
3. 验证鉴权、授权、租户、速率限制、幂等键和分页。
4. 比较新旧 Schema，检测删除、收紧、语义漂移和默认值变化。
5. 对关键消费者执行 provider/consumer 双向契约。
6. 验证响应后端数据、事件和审计副作用，而非只检查状态码。

## 不可违反的控制

- HTTP 2xx 不等于测试通过。
- Mock 契约必须由真实 provider 验证闭环。
- 错误响应不得泄露内部细节或跨租户信息。
- 版本兼容例外必须有到期时间。

## 完成判定

- 破坏性 API 变化在合并前被阻断。
- 关键操作覆盖成功、校验、鉴权、权限、限流和幂等。
- 消费者契约可定位受影响版本和服务。
- 所有请求响应证据完成脱敏。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
