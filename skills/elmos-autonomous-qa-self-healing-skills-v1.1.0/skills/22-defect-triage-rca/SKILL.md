# Defect Triage & Root Cause Analysis

## 目标

把大量失败聚类为真实缺陷，抑制级联噪声并定位最可能根因和最小复现。

## 何时调用

当工作流进入 `22-defect-triage-rca` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 失败测试、堆栈、日志、trace、metric 和数据 diff
- 代码变更、调用图、依赖拓扑和历史缺陷
- 环境/波动分类与需求追踪图

## 输出契约

- Defect 对象、严重度、优先级、影响面和所有者
- 根因候选、代码/配置引用、置信度和反证
- 最小复现命令、输入和证据包

## 执行步骤

1. 按错误签名、调用链、时间和共同依赖聚类失败。
2. 识别上游根因，抑制由同一故障造成的级联用例。
3. 将近期变更、代码所有权、历史缺陷和依赖异常关联。
4. 通过缩小输入、禁用无关路径和差分运行最小化复现。
5. 列出主假设、替代假设、支持证据和反证。
6. 根据用户影响、数据、安全和可恢复性评定严重度。

## 不可违反的控制

- 基础设施失败与产品缺陷必须分开。
- 置信度低时不得声称根因已确定。
- 同根因失败不应生成大量重复修复。
- 缺陷关闭必须有验证证据。

## 完成判定

- 每个高优先级缺陷有可运行最小复现。
- 聚类结果可解释且保留原始失败映射。
- 根因定位到可行动代码/配置/依赖。
- 严重度与影响基于规则而非主观文字。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## v1.1.0 产出关联

- 缺陷必须关联触发它的测试用例、测试文件哈希、环境、证据和最小复现脚本。
- 同一测试文件多个失败按共同根因聚类，但文件级失败记录不得丢失。
