# Safe Test Self-Healing

## 目标

修复因非语义 UI 结构、数据夹具、环境等待或版本化接口适配造成的测试脆弱性，同时防止测试被弱化。

## 何时调用

当工作流进入 `25-test-self-healing` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 确认属于测试/环境问题的 Defect
- 原需求、Oracle、历史稳定 locator/数据和 UI 语义
- 测试变更策略与变异基线

## 输出契约

- 测试/夹具/locator 补丁及理由
- 断言强度、需求覆盖和变异得分前后对比
- 稳定性验证与审批结果

## 执行步骤

1. 证明产品行为符合规格而测试实现失效。
2. 优先用可访问性语义或稳定测试 ID 替换 locator。
3. 用可观察条件替换 sleep，修复时间/随机/数据隔离。
4. 保持所有业务步骤和 Oracle；必要的 Oracle 变更单独审批。
5. 重复运行不同顺序、并行度和环境以验证稳定。
6. 比较覆盖和变异强度，任何下降拒绝补丁。

## 不可违反的控制

- 产品缺陷不得通过改测试关闭。
- 禁止扩大容差、忽略异常或删除步骤。
- 视觉基线不得自动无条件更新。
- 测试自愈补丁必须独立标识。

## 完成判定

- 修复后在稳定窗口内无波动。
- 需求映射和断言强度不下降。
- 变异得分不下降。
- 补丁原因可由独立 Reviewer 复核。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## 项目产出要求（v1.1.0）

- 本技能产生或修改的测试源、配置、数据、基线、报告、补丁或证据必须登记到 `ProjectOutputManifest`。
- 测试相关文件必须通过 `37-test-source-materialization` 写入目标生态原生目录；只存在于临时上下文不算完成。
- 任何文件变化都要更新 SHA-256、需求/用例引用和谱系；未登记文件不得进入最终 Bundle。
