# Governance, Approval & Audit

## 目标

对多租户权限、风险审批、代码所有权、预算、例外和审计保留进行强制治理。

## 何时调用

当工作流进入 `35-governance-approval-audit` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 用户/服务身份、租户、角色和属性
- 代码所有权、风险目录、审批矩阵和保留策略
- Run、RepairPlan、Patch、GateResult 和证据访问请求

## 输出契约

- 授权/拒绝决策、审批任务和签名记录
- 不可变审计日志、例外与到期提醒
- 租户隔离、预算和合规报告

## 执行步骤

1. 对每个 API、Worker、证据和补丁动作执行 RBAC/ABAC。
2. 根据路径、语义和数据分类计算修复风险与审批人。
3. 强制双人或多角色审批高风险修改。
4. 管理质量例外的范围、补偿措施和到期时间。
5. 审计策略、门禁、证据读取、补丁接受和证书签发。
6. 定期验证租户边界、最小权限和审计完整性。

## 不可违反的控制

- 审批人不得与生成高风险补丁的自动身份等同。
- 任何管理员覆盖都必须有理由和期限。
- 跨租户证据默认拒绝。
- 审计日志不可由普通服务修改或删除。

## 完成判定

- R3 修复无法绕过审批。
- 质量例外到期后自动失效。
- 所有敏感动作可按主体/资源/时间查询。
- 租户隔离和最小权限测试通过。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。
