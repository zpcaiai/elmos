# Runtime, Cost & ETA Estimation

## 目标

预测并持续校准 Elmos 自主测试/修复的机器 wall-clock、资源、token 和云成本，同时单独给出人工等效时间。

## 何时调用

当工作流进入 `31-runtime-cost-eta` 对应阶段，或上游技能产物变化导致本阶段失效时调用。不得跳过依赖技能直接伪造输入。

## 输入契约

- 测试图、历史时长、环境启动、分片与并行度
- 性能/耐久测试固定时长、失败概率和修复迭代分布
- CPU/GPU/浏览器/存储/网络/token 单价配置

## 输出契约

- 初始与实时 ETA、低/中/高置信区间
- 按阶段资源与成本预测、实际偏差和校准
- 人工手工设计/执行/定位/回归的等效时间对比

## 执行步骤

1. 为每类测试和环境维护历史时长分布。
2. 根据依赖图和资源并行度计算关键路径，而非简单求和。
3. 将排队、环境启动、重试分类、修复循环和全量回归纳入模型。
4. 运行中用已完成分片更新剩余 ETA。
5. 分别统计机器 wall-clock、总计算时长和人工等效时间。
6. 把预测误差回写模型并按仓库/测试类型校准。

## 不可违反的控制

- 不得把人日当作系统执行 ETA。
- 耐久/压力测试的最短业务时长不能被并行缩短。
- 成本预测必须标注价格配置时间和假设。
- 预算不足时明确报告未完成范围。

## 完成判定

- Run 创建后即有 ETA 区间。
- 运行中 ETA 随事实更新。
- 报告包含预测、实际、误差和原因。
- 机器与人工时间字段严格分离。

## 失败处理

- 输入缺失或 Schema 不合法：标记 `BLOCKED`，保留诊断，不得猜测为成功。
- 可恢复基础设施失败：保存检查点并按受限策略重试。
- 产品或策略失败：生成结构化缺陷/门禁结果，不得通过跳过或弱化规则绕过。
- 所有失败均写入证据清单和审计事件。

## v1.1.0 产出 ETA

- 系统 wall-clock ETA 必须包含测试文件生成/格式化/构建、哈希、Secrets 扫描、压缩、解压复验和上传发布时间。
- 报告测试执行时间与项目产出发布时间的分解，不使用人工工期替代系统时间。
