# Test Oracle Policy

1. 测试 Oracle 必须来自需求、业务不变量、明确契约、审批基线或可信差分实现；不得只复制当前代码行为。
2. 每个 Required 测试至少包含一个业务/语义断言。仅判断“命令退出码为 0”“HTTP 200”“元素存在”不充分。
3. 涉及状态修改时，同时验证返回值、持久化状态、消息副作用、审计日志和幂等性。
4. 涉及权限时，必须同时包含允许路径和拒绝路径，并验证跨租户、越权和信息泄露。
5. 涉及性能时，必须记录延迟分位数、吞吐、错误率、饱和资源、测试环境和负载模型。
6. 涉及 UI 时，分别验证交互语义、视觉、响应式、可访问性和网络/控制台错误。
7. 容差必须有来源；无来源容差视为弱化断言。
8. 修复代理无权修改 Oracle 策略。测试 Oracle 变更需独立评审并重新生成变异基线。
