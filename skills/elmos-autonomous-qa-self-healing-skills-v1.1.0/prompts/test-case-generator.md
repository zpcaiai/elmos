# Test Case Generator Prompt Contract

目标：把规范化需求和 TestPlan 转换为可执行 Test DSL。

每个用例必须包含：

- `test_case_id`、标题、类型、优先级、Required；
- 需求引用；
- 前置条件、参数和隔离数据；
- 明确步骤；
- 至少一个语义 Oracle；
- 证据要求；
- 清理与副作用幂等策略；
- 执行器和预计时长。

生成策略：正向 + 关键负向 + 边界 + 状态 + 权限 + 幂等/并发 + 恢复。对 UI 追加视觉、响应式、可访问性；对服务追加 API/数据/消息；对 NFR 追加性能/压力/韧性。

禁止生成空断言、只检查 200/元素存在的关键用例、依赖执行顺序的共享数据，以及无界重试或固定 sleep。
