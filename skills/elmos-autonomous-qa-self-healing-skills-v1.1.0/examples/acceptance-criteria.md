# 子系统验收标准

1. 给定同一需求、代码和配置快照，系统生成相同追踪节点、测试 DSL 和内容哈希。
2. 任一 Required 需求没有可执行测试时，发布认证失败。
3. 所有 Required 用例必须被实际调度并拥有合法终态；`SKIPPED` 不可发布。
4. 功能测试至少覆盖关键正向、负向、边界、状态、权限和幂等/并发路径。
5. UI 关键旅程具备交互、视觉、响应式、可访问性和浏览器矩阵证据。
6. 性能报告包含 p50/p95/p99、吞吐、错误率、资源、目标容量、最大稳定容量和压力拐点。
7. 客户端断线后服务端继续执行；编排服务或 Worker 异常后能从检查点恢复。
8. 缺陷自动修复只能在隔离分支执行；高风险变更无法绕过审批。
9. 修复不得删除测试、弱化断言或降低需求覆盖/变异得分。
10. 每个产品补丁必须通过原失败测试、影响回归与全量 Required 回归。
11. 报告中的每个结论、数字和补丁都能回链到不可变证据。
12. 报告明确给出系统自主 wall-clock ETA/实际耗时，以及单独的人工等效时间。
