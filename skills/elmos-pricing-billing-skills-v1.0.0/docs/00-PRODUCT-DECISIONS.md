# Elmos 收费体系核心产品决策

## D-001：采用四层混合收费，而非二选一

Elmos 的正式商业模型为：

1. **基础会员订阅**：支付平台能力、席位、协作、并发、保留期和基础设施固定成本。
2. **预充执行额度/按量结算**：覆盖模型、缓存、沙箱、测试、存储、网络和第三方工具等变动成本。
3. **项目封顶价或固定价**：用于范围、输入、验收和修改轮数明确的完整项目、迁移、转换和现代化任务。
4. **企业年度合同**：年度平台费、承诺用量、后付账期、私有化、SLA、专属支持、BYOK 和成本中心。

## D-002：对外不以原始 Token 作为唯一计价单位

Token、缓存、CPU/GPU、浏览器、测试、存储和网络是**内部成本核算单位**。普通客户看到的是货币金额、执行额度、费用区间、最大预算和实际结算。高级明细可展示 Token，但不得让用户仅靠 Token 判断总价。

## D-003：执行额度采用双余额模型

- `paid_credits`：用户付费获得；退款、到期和可转让规则由法域及合同决定。
- `promotional_credits`：订阅赠送、活动或补偿获得；允许设置有效期，不能伪装为现金资产。
- 展示层可以配置 `1 credit = 1 CNY` 等直观映射，但内部存储使用整数 `micro_credit`，且映射必须版本化。

## D-004：任务必须先报价、再授权、后执行

任何可计费任务都必须：

`estimate → quote → user acceptance → reserve/credit authorization → run → meter → capture/release → settle`

无有效报价或无预算授权不得启动可计费节点。

## D-005：默认使用费用区间与封顶价

- 探索性、小型和范围不稳定任务：按实际消耗，执行前给出 P50/P80/P90 区间。
- 中大型但仍有成本波动的任务：优先使用“实际结算、不超过 cap”的封顶价。
- 高标准化、低方差、验收明确的项目 SKU：才允许固定价。

## D-006：硬预算必须由执行控制面强制

50%、80%、95% 可作为默认提醒阈值；达到硬上限前，系统必须停止新的可计费调用并进入 `PAUSED_BUDGET`。只有用户追加授权或企业信用策略明确允许，才能继续。

## D-007：机器 ETA 与人工时间分开

报价卡必须显示：

- Elmos 自主生成/转换的**机器墙钟时间**；
- 传统人工开发的参考时间；
- 两者不得合并，也不得用人日替代机器 ETA。

## D-008：BYOK 不是免费模式

BYOK 用户自行承担其模型供应商账单；Elmos 仍可收取平台订阅、编排、沙箱、测试、存储、网络、监控和企业治理费用。原始模型密钥只存 secret manager 引用。

## D-009：账本是余额事实源

所有余额变更通过不可变双分录账本表达。余额表仅是投影，可随时从账本重建；禁止业务代码直接修改余额。

## D-010：失败结算按责任和用户获得价值处理

- 平台故障且用户未获得价值：自动免收或退款。
- 模型在预算内的正常自我修复：包含在任务预算中，不得无限加价。
- 用户、第三方、私有依赖或范围变更原因：可结算已发生且有价值的部分。
- 固定价未达验收：进入继续修复、部分退款、专家介入或合同终止。

## D-011：价格、合同和策略全部版本化

历史任务、发票、项目和退款必须绑定当时有效版本。新价格不得回写历史结算。

## D-012：示例价格不是生产承诺

本包的价格目录仅提供 `draft/example` 数据结构和参考套餐。生产价格必须经过财务、产品、法务/税务（适用时）和负责人审批。
