# 项目介绍与技术汇报 PPT 规范

## 演示类型

| # | 类型 | 建议长度 | 内容 |
|---:|---|---|---|
| 1 | 管理层项目介绍 | 10–15 页 | 问题、能力、规模、价值、状态、风险、路线 |
| 2 | 技术架构评审 | 15–25 页 | 上下文、服务、流程、数据、部署、安全、SLO、债务 |
| 3 | 新人培训 | 15–25 页 | 项目、目录、启动、核心流程、数据、常见任务 |
| 4 | 客户售前 | 10–20 页 | 痛点、能力、场景、架构、安全、部署、实施、价值 |
| 5 | 技术尽调 | 20–30 页 | 技术栈、成熟度、质量、安全、扩展、运维、风险 |
| 6 | 迁移翻新方案 | 15–30 页 | 当前、目标、顺序、数据、兼容、双运行、回滚 |
| 7 | 转换结果汇报 | 15–30 页 | 源目标映射、功能保持、失败、修复、性能、证据 |
| 8 | 生产认证 | 10–20 页 | 范围、门禁、证据、残余风险、E1–E5 |
| 9 | 项目周/月/季报 | 8–15 页 | 进度、质量、风险、成本、下一步 |

## 生成原则

- 一页一个主结论；
- 先结论，后证据；
- 事实数字必须有来源；
- 架构图/流程图来自 Diagram Spec；
- 代码片段短且可读；
- 使用原生可编辑文本、形状、表格和图表；
- 复杂图保留 SVG 与源 Spec；
- 支持品牌模板、Logo、字体替代、页脚、保密等级；
- 支持中文、英文、双语和演讲备注；
- 支持固定页、锁定元素和增量重生成；
- 每页保存 claim/evidence map；
- 输出 PPTX，PDF 仅作预览或分发。

## 自动 QA

- 文本溢出；
- 字号和对比度；
- 图表标签；
- 页码/目录；
- 断链；
- 证据缺失；
- stale claim；
- 敏感代码/秘密；
- 品牌不一致；
- PPTX 可打开与可编辑。
