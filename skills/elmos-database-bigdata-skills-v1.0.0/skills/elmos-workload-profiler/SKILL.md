# 数据与查询工作负载画像

## 目标

对样例数据、现有数据库、日志和查询进行安全画像，估算规模、分布、倾斜、热点与增长。

## 适用触发条件

- 存在样例数据或现有数据库
- 选型需要证据
- 需要容量或性能规划

## 输入

- WorkloadRequirementIR
- 脱敏样例或只读统计
- 查询日志与执行计划
- 数据字典

## 执行流程

1. **PROF-001** — 建立只读、最小权限、限流、超时和抽样边界，禁止破坏性生产访问。
2. **PROF-002** — 计算行数、字节、增长、基数、空值、重复、分位数、分布和字段相关性。
3. **PROF-003** — 识别分区倾斜、热键、热点租户、宽行、超大对象、小文件和高基数字段。
4. **PROF-004** — 分析查询过滤、连接、排序、聚合、扫描量、并发、缓存命中和慢查询。
5. **PROF-005** — 分析事件时间、乱序、迟到、水位、重放范围和状态大小。
6. **PROF-006** — 区分样本推断与真实监控值，输出脱敏画像、时间窗和置信度。

## 强制决策规则

- 先执行硬约束过滤，再做软评分；安全、合规、数据完整性和明确 SLO 不可被总分覆盖。
- 所有外部能力、版本、兼容性与性能声明必须绑定注册表或运行证据；模型记忆不能作为生产证据。
- 默认优先最简单、可运维、可恢复的方案；新增数据库或引擎必须证明其量化必要性。
- 多租户数据、缓存、日志、指标、密钥和证据必须按 tenant_id 隔离。
- 所有副作用任务必须有 idempotency_key、恢复点、重试分类和回滚/补偿语义。
- 输出必须区分 implemented、configured、tested、verified、certified。

## 必需产物

- `data-profile.json`
- `query-profile.json`
- `skew-and-hotspot-report.md`

## 验收标准

- 画像包含数据、查询、增长、热点和倾斜。
- 生产访问只读且可审计。
- 推断带样本范围与置信度。
- 可被容量和基准技能消费。

## 失败、降级与恢复

无法访问数据时以 schema、日志和业务上界建立保守模型，并标记未验证项。

失败时必须保存已完成节点、输入快照、输出校验和、日志、成本、模型调用、缺陷和剩余 DAG；恢复从最近幂等节点继续。
