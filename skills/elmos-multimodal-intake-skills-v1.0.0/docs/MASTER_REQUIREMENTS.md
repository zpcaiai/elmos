# Elmos 多模态输入、长上下文与项目包接入——主需求规格

**版本：** 1.0.0  
**基线日期：** 2026-08-19  
**规范范围：** 50 个 Skills 的统一产品、架构、安全、数据、执行和验收要求。

## 1. 目标

Elmos 必须提供一个基础设施级的 **Multimodal Intake & Understanding Platform**，把用户通过文本、音频、图片、文档、文件夹和归档提交的资料，安全地转换为统一、结构化、可索引、可追溯、可长期执行的项目上下文，并交给项目生成、代码转换、架构理解、测试、修复、文档和分析 Agent。

该平台不是“上传附件后抽一段文本”，而是以下闭环：

```text
接收 → 校验 → 隔离 → 解析 → 结构重建 → 多模态理解
→ 统一内容 IR → 来源证据链 → 跨文件融合/冲突
→ 索引/项目记忆 → 动态上下文装载 → 下游任务
→ 测试/反馈 → 修正版本 → 长期可恢复执行
```

## 2. 范围

### 2.1 首期输入

| 类别 | 格式/方式 | 最低能力 |
|---|---|---|
| 直接输入 | 文本、粘贴图片、麦克风录音 | 即时创建 InputSession |
| 音频 | MP3、WAV、M4A、AAC、FLAC、OGG、OPUS | VAD、语言识别、ASR、时间戳、说话人、置信度 |
| 图片 | PNG、JPG/JPEG、WEBP、HEIC、TIFF、BMP、SVG | 预处理、OCR、坐标、视觉/UI/图理解 |
| PDF | 原生、扫描、图文混合、用户提供密码的加密 PDF | 页级路由、版式、阅读顺序、表格、图片、OCR、来源框 |
| Word | DOCX、隔离转换的 DOC | 标题、段落、表格、图片、批注、修订、脚注、链接 |
| 文本 | Markdown/MDX、TXT、LOG | 结构、代码块、行号、编码、日志堆栈、配置检测 |
| 文件夹 | 单个/多个目录、文件混合 | 相对路径、目录树、清单、断点续传、项目角色 |
| 归档 | ZIP、TAR、TAR.GZ、TGZ、GZIP | 先检查后解压、沙箱、炸弹/穿越/链接防御 |

### 2.2 扩展接口

架构需为视频、字幕、Excel/CSV、PPTX、HTML/URL、7Z/RAR、Git 仓库、邮件、数据库导出、Figma 等保留 provider/parser adapter，不要求首期全部实现。

## 3. 用户与权限

最低角色：

- **Tenant Admin**：配置配额、provider、保留、安全和模型策略；
- **Project Owner**：管理项目包、项目版本、模型读取范围和任务；
- **Contributor**：提交资料、修正转录/OCR、启动获准任务；
- **Reviewer**：处理低置信度、冲突、安全和验收；
- **Auditor**：只读查看来源、事件、成本和安全证据；
- **Service Agent**：仅获得任务所需最小对象和工具权限。

每次对象访问必须同时过滤 `tenant_id`、`project_id`、ACL，涉及代码时还应固定 `package_version/branch/environment`。缓存、向量索引、对象存储路径、消息和 Trace 不能遗漏同一边界。

## 4. 核心领域对象

### 4.1 InputSession 与 Asset

- `InputSession`：一次用户提交的全部输入；
- `InputPackage`：可提交给下游任务的版本化资料集合；
- `Asset`：不可变原始文件或录音；
- `AssetVersion`：重传或新版本，不覆盖旧资产；
- `ProcessingJob`：解析/识别/索引阶段；
- `ProcessingCheckpoint`：阶段恢复点；
- `SecurityFinding`：病毒、宏、Prompt Injection、密钥、归档攻击等；
- `ProviderExecution`：每次 OCR/ASR/LLM/解析 provider 调用及成本。

### 4.2 统一多模态 IR

`ContentBlock` 至少支持：

```text
heading, paragraph, list, table, table_cell, image, figure,
audio_segment, transcript_turn, code_block, log_entry, formula,
form_field, comment, revision, diagram_node, diagram_edge,
ui_element, file, symbol, requirement, decision
```

每个块至少包含：

- `block_id`、`asset_id`、`package_version_id`；
- `block_type`、规范化内容、语言；
- 结构父子关系与阅读/时间顺序；
- 解析器/provider/模型版本和置信度；
- 一个或多个 `SourceAnchor`；
- 敏感/安全标签；
- 内容哈希和派生链；
- 处理状态、错误和修正版本。

### 4.3 SourceAnchor

统一来源锚点可表示：

- PDF 页码 + bounding box；
- Word part/标题/段落/表格/批注/修订；
- 音频 `start_ms/end_ms/speaker`；
- 图片 bounding box/polygon；
- Markdown 标题/代码块；
- TXT/LOG 行号或字节范围；
- 文件路径 + 行列/字节范围；
- 代码符号 id + commit/package version；
- 表格行列；
- 流程/架构图节点与连线；
- 工具运行 id、测试 id、Trace id。

关键需求、决策、缺陷和最终结论的来源覆盖率目标为 100%。定位变化时必须生成 anchor migration，而不是静默指向错误内容。

## 5. 输入和处理工作流

### 5.1 通用流程

```text
CREATED → UPLOADING → UPLOADED → VALIDATING
→ SCANNING/QUARANTINED
→ PARSING/TRANSCRIBING/OCR_PROCESSING/VISION_PROCESSING
→ NORMALIZING → FUSING → INDEXING
→ READY | PARTIALLY_READY | NEEDS_REVIEW | FAILED | CANCELLED
```

状态必须持久化，转换使用乐观锁或等价并发控制。状态和事件应以事务/outbox 保持一致。

### 5.2 上传

- 大文件分片，小文件可批量；
- 文件/分片内容哈希和幂等键；
- 服务端确认是恢复事实来源；
- 断网、页面关闭和客户端重启可继续；
- 客户端断开不取消服务端处理；
- 同内容去重不得造成跨租户信息侧漏；
- 单文件失败不重传整个文件夹；
- 包完成前校验 manifest 与对象一致；
- 展示真实上传/处理机器 ETA 和成本，不展示人工工期。

### 5.3 文件类型与安全扫描

扩展名、MIME、文件魔数和结构探测交叉验证。任何不匹配都产生 finding。解析器运行在无网络、受限 CPU/内存/磁盘/进程、硬超时、只读基础镜像的隔离沙箱。

输入阶段禁止执行：

```text
Office 宏、PDF JavaScript、嵌入脚本、Shell/PowerShell、
npm/pnpm/yarn install、postinstall、Makefile、Gradle/Maven task、
Dockerfile/Compose、动态库、二进制、项目初始化脚本
```

后续代码构建/测试必须进入另一套受控执行环境和审批边界。

## 6. 模态要求

### 6.1 音频

- 自动语言识别、中英文混合、VAD、降噪；
- 说话人分离，支持人工更正；
- 词/句级时间戳、置信度、专业词表；
- 长音频切片并在边界重叠合并；
- 点击文本跳音频；局部重识别；
- 转录修正版本化并保留原始；
- 从转录抽取需求、约束、验收、决策和待确认项；
- 口述高风险指令不直接产生副作用，仍受工具权限和审批。

### 6.2 图片

- 旋转、倾斜、降噪、透视、方向、切片；
- OCR 文本及 polygon/bbox；
- UI 元素树、交互、页面状态、设计 token；
- 架构/流程/数据流/UML/ER 的节点、边、方向、边界；
- 错误截图、日志截图、代码截图识别；
- 视觉模型不确定结果标置信度和替代候选；
- 视觉描述不能替代原始图片锚点。

### 6.3 PDF

- 区分原生、扫描、混合页并逐页路由；
- 保留页码、标题、段落、多栏阅读顺序、页眉页脚、目录；
- 表格、合并单元格、图、图注、公式、代码、脚注、表单；
- 每个块保留页码和坐标；
- 用户提供密码只进入短期秘密通道；
- 不破解密码，不绕过权限；
- PDF 中脚本、附件和可疑动作仅作为安全元数据。

### 6.4 Word

- DOCX 原生 OOXML；旧 DOC 在隔离环境中安全转换；
- 标题、编号、表格、图片、文本框、页眉页脚、脚注/尾注；
- 批注、修订、删除内容、作者/时间（按隐私策略）；
- 支持最终版、全部修订、差异和待办提取视图；
- 宏和嵌入对象不执行。

### 6.5 Markdown/TXT/LOG

- Front Matter、标题、引用、表格、任务列表、代码块、MDX 边界、Mermaid、公式；
- 保留行号、字节范围、编码和换行；
- UTF-8/UTF-16/GBK 等编码探测；
- 日志时间、级别、trace、异常堆栈、重复聚合；
- JSON/YAML/XML/配置仅解析，不执行；
- Markdown 中的“忽略系统指令”等内容是数据，不是 Agent 指令。

## 7. 多文件融合和需求理解

一次 InputPackage 可含需求 PDF、Word 验收、UI 截图、会议录音、Markdown 约束和日志。系统应：

1. 识别资料角色、项目、版本、主/补充/历史关系；
2. 进行精确和语义去重；
3. 抽取功能、非功能、业务规则、技术约束、优先级和验收条件；
4. 建立实体、关系、数据流和依赖；
5. 检测矛盾，不静默选择；
6. 依据显式优先策略给出建议，但用户可确认；
7. 每条需求关联一到多个来源和冲突状态；
8. 下游生成/测试将 requirement id 和 source anchors 带入证据。

推荐优先级只是一项可配置策略，例如：

```text
用户指定主版本 > 已批准/签署资料 > 最新有效决策
> 最新会议记录 > 当前原型 > 历史参考
```

不能把优先级当作删除其他证据的理由。

## 8. 文件夹与项目包

### 8.1 文件夹

- 只记录相对路径，不采集 `/Users/...`、`C:\...`；
- 保留目录、空目录、点文件、同名不同路径；
- 跨平台处理 Unicode、大小写、保留名、分隔符；
- manifest 协商、内容哈希去重、文件级和分片级恢复；
- 上传中变化的文件必须重新校验；
- 支持多根目录及主项目/辅助/参考/文档/测试数据角色。

### 8.2 归档

支持 ZIP、TAR、TAR.GZ、TGZ、GZIP。必须先流式检查：

- 类型与加密状态；
- 声明/实际展开大小；
- 文件数、单文件大小、目录深度；
- 压缩比、嵌套深度和累计预算；
- 路径、链接、特殊文件和覆盖碰撞。

解压防御：

- 拒绝 `../`、绝对路径、盘符、UNC、NUL、编码混淆；
- 最终解析路径必须位于已打开的沙箱根句柄内；
- 不跟随符号链接/硬链接；
- 不创建设备、FIFO、socket、setuid；
- 防 TOCTOU 和链接链绕过；
- 嵌套归档共享全局预算；
- 超限立即终止并隔离；
- 密码不出现在日志、数据库明文、Trace 或模型上下文。

### 8.3 项目识别

根据构建清单、依赖、目录、内容和框架特征识别：

- Java/Kotlin/Python/C#/Go/Rust/C/C++/PHP/TS/JS/React/Vue/ObjC/Swift/Flutter 等；
- Maven/Gradle/.NET/MSBuild/Cargo/Go Modules/CMake/Make；
- npm/pnpm/Yarn/Bun/Vite/Next/Nuxt/Angular；
- Poetry/uv/pip/Conda、CocoaPods/SPM；
- Docker/Kubernetes/Terraform 等。

必须支持 monorepo、多模块、多个独立项目和混合资料包。结论带置信度和证据，低置信度由用户修正。

### 8.4 分类和忽略

综合 `.gitignore`、`.dockerignore`、`.npmignore`、`.elmosignore`、系统规则与用户选择。条目状态至少包括：

```text
Included, MetadataOnly, Excluded, Quarantined,
Generated, Vendored, Binary, SecretSuspected
```

忽略只产生分析视图，不从原始 manifest 删除条目。安全隔离和敏感发现优先于普通 include。

## 9. Repository Map 与增量版本

Repository Map 应覆盖：

- 项目、模块、包/命名空间；
- 类、接口、函数、字段、路由、API；
- 数据实体、SQL、消息主题、配置；
- 构建、部署、测试；
- import、调用、继承、实现、读写、消息、测试关系；
- 文件路径、源码范围、哈希、版本和置信度。

索引阶段不得执行项目代码。动态/反射关系以候选和置信度表示。

每次导入创建不可变 `PackageVersion`。通过哈希识别新增、修改、删除、未变和重命名候选；未变解析产物复用。运行中任务固定输入版本，不得静默切换到新包。增量索引结果必须与同版本全量重建通过一致性检查。

## 10. Codex 同级动态长上下文

### 10.1 基线与动态能力

截至 `2026-08-19`，包的兼容测试夹具使用：

```yaml
context_window_tokens: 1050000
max_output_tokens: 128000
```

这是带日期的 Codex 对齐基线，不是永久业务常量。生产通过 `ModelCapabilitySnapshot` 获得：

- provider/model/version/alias；
- 总上下文和最大输出；
- 输入模态、工具/结构化输出能力；
- 价格和区域；
- 声明值、实测值、租户限制；
- 来源、获取时间和可信状态。

模型切换或能力变化后自动重算预算。未知能力按保守限制处理。

### 10.2 三种容量

```text
原始资料容量 ≠ 活动上下文容量 ≠ 项目长期记忆容量
```

用户可以提交超过 1.05M token、甚至多 GB/数万文件的项目，受租户存储和处理配额控制。系统全量保存、解析和索引，但当前模型只装载最相关证据。

### 10.3 有效输入预算

```text
有效输入 =
总窗口
- 系统/安全/租户策略
- Skill/工具定义
- 当前对话
- 输出预留
- 未来工具结果预留
- 推理/安全 headroom
```

所有文本、代码、OCR、ASR、图片等价 token、工具 schema/结果和记忆块都计量。当前窗口占用、历史累计 usage 和费用必须分开。

### 10.4 分层装载

```text
L0 项目全局地图
L1 领域/模块摘要
L2 当前工作流模块
L3 直接修改文件
L4 符号/调用/测试
L5 原始证据
```

P0/P1（安全、当前用户指令、硬约束、验收）不可驱逐。候选通过关键词、向量、符号图、调用图、版本、时效、可信度和 token 成本混合排序，并执行去重与来源多样性约束。

### 10.5 压力和结构化压缩

默认可配置状态：

```text
NORMAL <65%
ELEVATED 65–80%
HIGH 80–90%
CRITICAL >90%
```

使用迟滞避免抖动。压缩结果不是一段摘要，必须包含：

- 目标、最新要求、约束、验收；
- 已批准/否决决策；
- 已完成和未完成工作；
- 修改文件和版本；
- 测试、失败、安全发现；
- 副作用和成本账游标；
- 来源锚点、内容哈希、检索键；
- 下一动作与回滚引用。

压缩前后运行完整性门，关键事实保留率目标 100%。原始历史外置但可恢复。多轮压缩检测语义漂移。

### 10.6 检查点、恢复和重新水化

- 安全边界、外部副作用前后、压缩前后和阶段结束创建检查点；
- 客户端断开不取消任务；
- 服务重启从最后安全点恢复；
- 幂等键和副作用账本防重复支付/发送/写入/计费；
- 重新水化优先按原始页码、时间、框、行号、符号和版本精确加载；
- 来源缺失或哈希不符不能用摘要冒充原始证据；
- 重新装载后仍需通过预算和完整性门。

## 11. API 和事件

API 必须：

- 版本化 `/api/v1`；
- 使用 OAuth/OIDC 或现有 Elmos 身份；
- 对创建/完成/重试/恢复接口支持 `Idempotency-Key`；
- 长任务返回 job id；
- SSE/WebSocket 仅用于订阅，事实状态在数据库；
- Webhook 签名、重放防护和投递幂等；
- 错误含稳定 code、trace id、retryable 和安全信息；
- 列表分页、过滤、限流；
- OpenAPI/SDK 与实现同步。

完整建议见 `docs/API_AND_EVENTS.md`。

## 12. 进度、ETA、成本和收入

每个任务/阶段报告：

```text
status, progress, elapsed_seconds,
estimated_remaining_seconds, estimated_completion_at,
estimate_confidence, model_cost, compute_cost, storage_cost,
total_cost, billable_amount, pricing_version, trace_id
```

ETA 是 Elmos 自身机器 wall-clock 时间，基于文件大小、页数、音频时长、OCR比例、模型/硬件、队列、历史实际和当前阶段；禁止用人日替代。估计结束后用实际值回填并持续校准。

费用账必须区分：

- provider 输入/输出/缓存/图像/音频费用；
- CPU/GPU、对象存储、索引和网络费用；
- 重试/恢复费用；
- 租户价格、折扣、收入和毛利；
- 幂等去重，防重复计费；
- 估算、预留、实际和结算状态。

## 13. 安全和隐私

最低控制：

- MIME/魔数/结构验证；
- 病毒、宏、脚本、嵌入对象、压缩炸弹和路径穿越；
- 解析器供应链签名/SBOM/漏洞更新；
- Prompt Injection 检测和数据/指令通道隔离；
- 工具白名单、参数级权限、审批和出网控制；
- `.env`、私钥、token、连接串、PII 检测与遮蔽；
- 原始/派生加密、租户密钥策略；
- 临时密码/秘密短期存储和销毁；
- 最小日志，不记录文件正文、密码或密钥；
- 保留、法律保留、导出和完整删除；
- 审计不可抵赖和安全事件响应。

安全发现不能被普通 ignore、模型提示或用户内容覆盖。

## 14. 工作台

统一输入工作台至少提供：

- 文本、文件、文件夹、归档、粘贴图片、麦克风；
- 每项上传/扫描/解析/索引状态和真实机器 ETA；
- 页/音频/图片/目录预览；
- OCR/ASR 修正；
- 多文件角色、版本和冲突审查；
- 目录树虚拟化；
- 项目根、语言、框架、ignore 和模型读取范围；
- 安全、敏感、低置信度和失败告警；
- 活动上下文仪表盘：模型、总窗口、已用、输出预留、可用、来源分类；
- 区分已上传、已解析、已索引、活动加载、可检索未加载、隔离、失败；
- 无障碍、国际化和大数据量性能。

## 15. 非功能要求

### 15.1 可靠性

- durable workflow；
- at-least-once 事件配合幂等消费者；
- 检查点、超时、退避、熔断、死信和人工恢复；
- 部分失败隔离；
- 数据库/队列/对象存储一致性对账；
- 灾备 RPO/RTO 由部署策略定义并测试。

### 15.2 性能

指标必须绑定参考硬件和数据集，至少测：

- 上传吞吐、断点恢复；
- 页/分钟 OCR，音频 realtime factor；
- 10万条目 manifest/目录树；
- ZIP/TAR 展开吞吐与提前阻断；
- 100k 文件仓库索引；
- 混合检索 P95；
- 上下文装箱/压缩/水化延迟；
- API P50/P95/P99；
- 峰值CPU、GPU、内存、磁盘和对象存储。

### 15.3 质量

建议基线目标，需以实际数据集校准：

- 有效声明格式解析成功率 ≥99.5%；
- 清晰印刷 OCR 字符准确率目标 ≥98%；
- 清晰普通话 CER 目标 ≤8%；
- 清晰英语 WER 目标 ≤10%；
- 关键来源锚点覆盖率 100%；
- 关键上下文事实保留率 100%；
- 跨租户泄露和归档逃逸 0；
- 低置信度必须显式标记。

## 16. 验收场景

### 16.1 多模态联合

上传需求 PDF、Word 验收、两张 UI、会议音频、Markdown 约束和日志。要求：

- 全部解析并带来源；
- 抽取需求；
- 检测登录方式冲突；
- 用户修正音频；
- 生成下游任务；
- 测试报告能回溯关键来源。

### 16.2 超长上下文

```text
语料 ≥ 2,000,000 tokens
活动窗口始终 ≤ 模型有效预算
至少 3 次结构化压缩
至少 5 次精确重新水化
完成代码修改和真实测试
关键事实和来源无静默丢失
```

### 16.3 大项目包

```text
100,000 个文件
monorepo + 多语言 + 文档 + 测试数据
网络中断后恢复
增量版本仅重建受影响范围
目录/索引/上下文状态透明
```

### 16.4 恶意归档

覆盖 Zip Slip、绝对路径、UNC、编码混淆、符号链接链、硬链接、设备文件、稀疏文件、超高压缩比、嵌套炸弹和加密包。目标：无宿主写入、无沙箱逃逸、无资源失控、无密码泄露。

### 16.5 恢复与计费

在模型调用前后、外部副作用前后、数据库提交和队列发送之间注入故障。反复恢复后：

- 结果一致；
- 无重复副作用；
- 无重复 provider 计费记录；
- 成本账可对账；
- 客户端可重新连接并取得完整进度与结果。

## 17. 排除项

本包定义实现规范，不包含：

- 绕过加密文档/归档密码；
- 在接入阶段执行用户代码；
- 未经许可把私密文件发送给第三方模型；
- 无来源的自动业务决策；
- 将所有项目文件无差别塞入一个模型请求；
- 以 Mock、禁用测试、固定假数据代替生产实现；
- 用人工工期冒充 Elmos 运行 ETA。
