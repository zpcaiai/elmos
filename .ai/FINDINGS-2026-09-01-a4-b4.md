## 1. 结论先说

1. **B4 的选型结论仍然成立，但理由要换。**
   演示用 **Matrix Synapse 的真实生产 schema**，理由不再是"因为自家迁移只有 18.9%"，
   而是：**它是唯一一个整文件解析零失败、语句量够大（417 条）、schema 占比高（397/417）
   的候选**。同一批候选里 pagila / sakila(pg) / chinook 都会整文件解析失败，northwind 被
   3300 多条 INSERT 种子数据把分母冲垮。见 §2.2 的头对头表。

2. **"用 ELMOS 自家迁移会难看"这个前提已经过期。**
   自家 `modules/persistence` 迁移今天实测 **schema 语句 83.30%**（1152/1383），
   不是 18.9%。引擎在 2026-08-21 之后新增了 routine / static-DO / comment / privilege /
   RLS / DML 等多个 certified profile，正好吃掉了"塞满 `DO $$` / RLS / 触发器 / `COMMENT ON`"
   这批语句。**但演示仍然不建议用它**——理由变成了：81 个文件里有 **9 个整文件解析失败**
   （占 242 KB），现场解释成本高。

3. **"故意超出子集"的语句集不需要编。**
   Synapse 那一份文件自己就带 42 条被拒语句、6 个原因码。演示时用**同一个文件**
   讲"这些进了、这些没进、为什么"，比另开一个人造文件强得多。人造集只用来补
   `NAMESPACE_MAPPING_REQUIRED` / `UNBOUNDED_DECIMAL` / `INDEX_PREDICATE` 这三个
   Synapse 里没有的原因码（§4）。

4. **顺带核实到 4 条 backlog 前提的真实状态**（§5），其中 A1 的开放前提①有明确答案了。

## 5. 顺带核实到的 backlog 前提（都是真跑出来的）

### 5.1 A1 开放前提①：`run_spring_boot_reference.py` 能不能指向任意仓库 → **不能**

```
$ python3 scripts/batch30/run_spring_boot_reference.py --help
usage: run_spring_boot_reference.py [-h] [--repo-root REPO_ROOT]
```

只有 `--repo-root`，而且 `main()` 里 `repo = Path(args.repo_root).resolve(); pack = execute(repo)`
—— **`--repo-root` 是 elmos 仓库根，不是被翻新的客户工程**。参考工程由脚本内部构造，
`transform_with_openrewrite()` 把 `source` 目录 `copytree` 到 `target` 再装配方。
另外脚本头部把 JDK 路径写死成 macOS 专属：

```python
SOURCE_JAVA = Path("/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home")
TARGET_JAVA = Path("/opt/homebrew/Cellar/openjdk@21/21.0.11/libexec/openjdk.jdk/Contents/Home")
```

**所以 A1 是"先改脚本"，不是"喂语料"，而且改完仍然是 Mac-only。**
backlog 里那句"这条前提没核实之前不要报工期"现在可以解锁了，工期要按"先加外部仓库入口"排。
