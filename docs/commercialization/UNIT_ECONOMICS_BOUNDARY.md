# D-04 边界分析：不等实测，今天能得出的定价结论

日期：2026-07-29
工具：`scripts/commercial/break_even_token_price.py`
输入：`scripts/commercial/model-prices.json`（全部带可核对来源 URL）
关联：[`UNIT_ECONOMICS.md`](UNIT_ECONOMICS.md)、`scripts/commercial/unit_economics.py`

---

## 0. 这份文档解决什么

`unit_economics.py` 要 16 个成本输入，其中 8 个**只能从自己系统实测**：
token 输入/输出结构、缓存命中率、Runner 单位成本、人均产物体积、
人均出网量、人工支持成本、实际使用率。这些今天拿不到，
所以 `costValidationStatus` 卡在 `NOT_RUN`，目录卡在 `DRAFT`。

但有一类结论**不需要**那 8 个输入：

> 标价扣掉税和通道费之后，付完 token 还剩多少钱？
> 剩下的够不够付 Runner + 存储 + 出网 + 支持？

这算的不是毛利，是**毛利的上界**。上界为负 → 这个价无论如何都亏，
不用等实测就能排除。上界为正 → 还不能下结论，但能知道离红线多远、
哪个变量最要命。

## 4. 换算成可以直接比价的数字

目录里 `isolated-runner-minute = 1 Credit`。把余量除以 Credit 数，
得到**每分钟隔离机时的可承受成本上界**，再与真实实例单价比：

| 组合（输出占比 30%） | 每分钟上界 | ÷ ¥0.00375（2C4G 最低价） | 判断 |
|---|---|---|---|
| 月付 × V4-Flash | ¥0.1568 | **42×** | 宽裕 |
| 月付 × Qwen3-Plus | ¥0.1602 | **43×** | 宽裕 |
| 月付 × V4-Pro | ¥0.0699 | **19×** | 可行，但要盯住 |
| 年付 × V4-Flash | ¥0.0933 | **25×** | 宽裕 |
| 年付 × Qwen3-Plus | ¥0.0968 | **26×** | 宽裕 |
| 年付 × V4-Pro | ¥0.0064 | **1.7×** | **不可行** |

"42×" 的含义是：把全部 600 Credit 换成隔离机时、且机时成本是最便宜实例的
42 倍时才打平。这个倍数就是留给存储、出网、人工支持、退款与坏账的空间。

## 5. 今天就能下的三个结论

### 5.1 模型档位是这门生意的主变量，不是配置项

`elmos-pro-annual` 配 Pro 级模型，在输出占比 50% 时**光 token 就亏 ¥9.95/月**；
在 30% 时只剩 ¥4.83/月覆盖 750 分钟机时 + 存储 + 出网 + 支持——
折合每分钟 ¥0.0064，只有最便宜实例单价的 1.7 倍。这不需要实测就能排除。

同一个套餐配 Flash 级模型有 25 倍空间。**同一个价格，模型档位一换就从"很宽裕"
变成"必亏"。** 因此"用哪个模型"必须写进定价目录的前置决策，
而不是留给运行期配置。目前仓库里**没有任何地方记录了这个选择**——
`grep` 遍 `deploy/`、`application.yml`、`docs/commercialization/` 都没有模型 ID。

### 5.2 年付比月付更薄，不是更厚

年付折月 ¥107.58 vs 月付 ¥126.67（-15%），额度却更高（25M vs 20M token，
750 vs 600 Credit）。**年付在给折扣的同时加了量**，两头挤压。
这是常见的定价反模式：年付通常用来换现金流与留存，代价应该是折扣，
不应该同时加量。若要保留年付折扣，额度应与月付持平或更低。

### 5.3 `taxPresentation: UNSPECIFIED` 必须先解决

它决定净收入是 ¥118.78 还是 ¥126.67，是上表每一格的基数。
另外，如果主体是**小规模纳税人**，2026–2027 期间征收率 3% 减按 1%，
净收入会高约 5 个百分点——这又反过来影响"要不要一开始就登记为一般纳税人"。
这是税务与定价耦合的地方，值得在办执照阶段一并决定。

## 6. 仍然 NOT_RUN（必须实测，不能推算）

| 输入 | 怎么拿到 |
|---|---|
| 真实输出 token 占比 | 在 `/generation` 的 16 个 PostgreSQL Profile 跑一遍，记录四类 token |
| 缓存命中率 | 同上；命中率高会显著压低成本（V4-Flash 缓存命中价只有 1/50） |
| 实际使用率 | 需要真实用户；试用期数据可作下界 |
| Runner 单位成本 | 定机型后即可算出，**今天就能做** |
| 人均产物体积 / 出网量 | 从现有 Profile 运行的产物大小估，需要仪表化 |
| 人工支持成本 | 与支持模式绑定（自助 / 邮件 / IM），是产品决策不是测量 |

前两项与 Runner 单位成本可以在**没有任何外部审批**的前提下完成——
它们不依赖营业执照、商户号或备案。这是当前唯一一条不被外部依赖阻塞的路径。

    --prices  scripts/commercial/model-prices.json

    --catalog contracts/pricing-catalog-schema/elmos-cny-self-serve-v1.json \

价格会变。`model-prices.json` 里的 `checkedOn` 就是给这件事用的——
超过一个季度没更新的价格，结论应当视为过期。
