## 0. 一句话结论

代码侧的"能卖的东西"基本齐了，**卡住商业化的不是功能，而是三件事：没有托管执行面、
没有生产部署与 SRE、没有收款主体**。

**2026-07-28 决策更新**：D-01 选定**中国大陆主体 + 支付宝/微信支付**，
D-03 选定 **SaaS 多租户托管**。这两个选择各自都是合理的，但它们**同时**去掉了本文
早先估算里的两条捷径——Stripe 零改动接入、以及"先单租户跑起来"。工作量因此上修：

| 路线 | 工程工作量 | 日历时间（含外部流程） |
|---|---|---|
| **最小可运营版**（只卖"多语言项目生成"，SaaS + 支付宝或微信二选一） | **24–32 人周** | 14–20 周 |
| **完整商业化运营**（三条业务线 + 企业级 SLA/安全/合规） | **36–52 人周** | 6–9 个月 |

单人全职推进：最小版约 6–8 个月，完整版约 9–12 个月。
三人团队：最小版 8–11 周，完整版 3–5 个月。

变化的来源（对比决策前的 11–15 / 30–44）：

| 项 | 决策前 | 决策后 | 原因 |
|---|---|---|---|
| 支付 | 3.5–5 | **7.5–10.5** | 大陆两家都要自建适配器 + 发票能力 |
| 托管执行面 | 6–8（可先单租户） | **8–12** | SaaS 强制 Runner Agent，单租户令牌路径必须删除 |
| 身份 | 2–3 | **3–4** | 组织自服务从"可延后"变成上线必需 |
| 安全合规 | 1–2 | **2–3** | ICP 备案 + 可能的等保定级 |

**日历时间比工程时间更值得盯**：ICP 备案（2–4 周）+ 支付商户审核（2–6 周）
是串行且不可压缩的，且都要先有营业执照。这条链应当今天启动。

**这三条 critical 就是商业化的硬门槛**，任何一条未闭合都不应对付费客户承诺 SLA。

## 2. 真实可售范围（必须先收敛）

不要卖"能力目录"，要卖**有端到端执行证据的东西**。按仓库证据分三档：

### A 档 — 现在就能卖（有真实构建/启动/测试证据）

**多语言项目生成 `/generation`**
- 8 个目标：Java 21/Spring Boot、Python 3.12/FastAPI、C#/.NET 10、TS/NestJS-Fastify、
  Go/net-http、Kotlin/Ktor、PHP、Rust/Axum
- `scripts/run_production_matrix.py` 对 8 × JWT/OIDC 共 16 个 Profile 用真实 PostgreSQL 17.5
  跑通迁移、鉴权负向路径、CRUD、RLS 跨租户隔离
- **边界（必须写进销售材料）**：Java/Python 支持多实体与关系；Go、TS、C#、Kotlin、Rust、PHP
  当前为**单实体**精确边界，多实体请求失败关闭

### B 档 — 可做 POC / 按项目收费，不能按订阅承诺

**Spring 老项目翻新 `/spring`**
- 只有 **Boot 2.7.18 / Java 17 / Maven** 一个元组有 `PASSED_LOCAL` 端到端证据
- Boot 1.5.x、2.0–2.7 其余版本、3.0–3.5 区间均为 `NOT_RUN`，需显式开
  `experimental-routes-enabled` 才执行
- **Gradle 明确 `NOT_IMPLEMENTED`** —— 这会砍掉相当比例的真实客户仓库

**Git 仓库接入 `/repositories`**（GitHub / Gitee / 通用 HTTPS）
- 私有实仓 E2E、子模块、LFS、推送/PR 均 `NOT_RUN`

### C 档 — 现阶段不能卖，只能作为路线图

- 整库跨语言转换 `/translation`：仅 `typed-pure-function-v1` 与 `repository-pipeline` 有证据；
  对象图、异常、异步、I/O、框架、数据库、并发**均未验证**
- 各类企业 Batch 12–18（多租户平台、商业闭环、生态增长、公司操作系统、AI-native、行业方案、
  集团整合）：全部是**只读证据裁判控制层**，`external_operation_executed=false`，不执行任何真实操作
- Batch 1–55 中 M1–M28 的 448 个契约为"来源不完整的规范化版本"，B40B–B55C 的 752 个契约为
  "规划版"——**这 1,200 个 Skill 不能出现在任何付费承诺里**
- `modules/lowering` 五模块链已被 ADR-0023 明确闭环，**不在任何已发布业务线的请求路径上**

> 商业化第一动作不是写代码，是把对外能力声明从"1,824 个 Skill / 20 个引擎"收敛成
> "A 档 1 条 + B 档 2 条"。否则第一个企业客户的技术尽调就会把整个可信度打穿。

## 3. 缺口清单与工作量估算

估算单位：**人周**（1 名有经验的全栈/平台工程师全职一周）。估算基于仓库现有代码结构，
不含需求变更与返工缓冲。

### G1. 托管执行面（Hosted Runner Fleet）—— 最大缺口

**现状**：产品的核心动作（生成、构建、启动探针、Spring 升级、整库转换）都必须在
rootless 容器里执行。今天的执行器 `ELMOS_LOCAL_RUNNER_EXECUTOR=ROOTLESS_CONTAINER`
是**开发者本机单节点**方案：默认关闭、需要绝对路径的 podman/docker、
`ELMOS_LOCAL_RUNNER_ROOT` 专用目录、且令牌**唯一绑定一个 tenant + 一个 actor**、
有效期 ≤ 24 小时。

**这意味着：现在没有任何一个客户能在不接触服务器 Shell 的情况下用这个产品。**

需要做的：

| 项 | 内容 | 人周 |
|---|---|---|
| G1.1 | 选定并落地基础设施（K8s 或 VM + rootless podman 池）+ IaC | 2–3 |
| G1.2 | 多租户 Runner 调度：排队、配额、并发上限、超时、抢占 | 3–4 |
| G1.3 | 镜像供应链：构建、签名、按 `name@sha256` 固定、私有 registry | 1–2 |
| G1.4 | 产物存储与生命周期：对象存储、按套餐保留期（7/30/90 天）自动清理 | 1–2 |
| G1.5 | 令牌模型改造：从"单租户单 actor 长期变量"改为服务端签发的短期作业令牌 | 2–3 |
| G1.6 | 隔离验证：只读根、能力移除、默认拒绝网络、CPU/内存/PID 限额的真实断言 | 1–2 |
| **小计** | | **10–16** |
