# Runner Agent 实现规格（路线 A）

生成日期：2026-07-28
触发决策：**D-03 = SaaS 多租户托管** → 路线 B（podman remote）被排除
状态：**规格，未实现**。本文不产生任何实现或隔离证据。

---

## 1. 为什么必须做

今天的执行面是：Web Console 的 BFF 进程直接调用**本机** podman，
凭一个绑定"单租户 + 单 Actor"、有效期 ≤24 小时的环境变量令牌。

选了 SaaS 多租户之后，这套东西有三个致命问题：

1. **一个令牌只能代表一个租户**。多客户共用一套部署时，要么所有客户共享同一个
   Actor 身份（审计与隔离直接失效），要么每客户一套部署（成本模型崩掉）。
2. **客户代码派生的构建过程和产品进程同机**。共享内核、共享磁盘、共享网络命名空间的
   宿主，一次容器逃逸就是全平台事故。
3. **令牌 24 小时过期**。有人得每天手动续，否则整个执行面停摆——
   这在有付费客户之后是不可接受的运维负担。

路线 B 只解决第 2 条。所以 SaaS 形态下只能走路线 A。

---

## 2. 目标架构

```
   ┌──────────────────────────────────────────────┐
   │ 应用主机（无 podman，不执行客户代码）           │
   │   web-console / control-plane                │
   │   commercial-api  ← 额度预留/结算              │
   │   job-dispatcher  ← 新增：队列 + 配额 + 令牌签发 │
   └───────────────┬──────────────────────────────┘
                   │ mTLS，单次作业令牌（≤15 分钟）
   ┌───────────────▼──────────────────────────────┐
   │ Runner 主机（独立机器，无业务数据库访问）        │
   │   runner-agent  ← 新增                       │
   │     └─ rootless podman，一作业一容器            │
   └───────────────┬──────────────────────────────┘
                   │ 只回传：状态、日志摘要、产物摘要
   ┌───────────────▼──────────────┐
   │ 对象存储（产物，按套餐保留期）    │
   └──────────────────────────────┘
```

**关键约束：Runner 主机不持有数据库凭据、不持有支付凭据、不持有其他租户的任何数据。**
它拿到的只有"这一个作业"所需的输入和一个马上过期的令牌。

## 3. 作业令牌模型（替换现有环境变量令牌）

### 3.1 签发

由 `job-dispatcher` 在**接受作业时**签发，不是配置出来的：

```
claims:
  jti          作业唯一 ID（一次性，用过即废）
  tenant       从认证会话派生，不来自配置
  actor        从认证会话派生
  job          作业 ID
  scope        本次允许的动作，如 ["generate", "build", "probe"]
  image        允许使用的镜像摘要 name@sha256:<64hex>
  limits       cpu / memory / pids / wallclock
  exp          ≤ 签发后 15 分钟
```

签名用非对称密钥；Runner 只持有公钥，**不能自己签发令牌**。

### 3.2 校验（Runner 侧，逐条失败关闭）

| 检查 | 不通过时 |
|---|---|
| 签名有效 | 拒绝 |
| `exp` 未过期 | 拒绝 |
| `jti` 未被使用过（本地重放缓存） | 拒绝 |
| `image` 是 `name@sha256:<64hex>` 形式 | 拒绝 |
| 请求的动作在 `scope` 内 | 拒绝 |
| `limits` 不超过 Runner 的硬上限 | 拒绝（取小者，不取令牌值） |

### 3.3 迁移路径

`ELMOS_LOCAL_RUNNER_AUTH_TOKEN` / `_TENANT_ID` / `_ACTOR_ID` / `_EXPIRES_AT`
四个变量在 Runner Agent 上线后**全部删除**，不保留兼容分支——
保留兼容分支等于保留一条绕过多租户隔离的后门。

## 4. 队列与配额

定价目录已经声明了并发上限，Runner 必须真实强制，不能只在 UI 上显示：

| 套餐 | `concurrentJobs` | `activeProjects` | 产物保留期 |
|---|---|---|---|
| 免费体验 | 1 | 1 | 7 天 |
| 专业月付 | 3 | 10 | 30 天 |
| 专业年付 | 5 | 25 | 90 天 |

规则：

- 队列**按租户分片**，一个租户排队不影响其他租户（避免大客户饿死小客户）
- 超过 `concurrentJobs` 的作业**排队**，不是拒绝，但要给出排队位次
- 作业开始前先向 `commercial-api` **预留**额度，结束后按实际用量**结算**，
  失败/取消要**释放**——这三个动作既有实现已具备，Runner 只需正确调用
- 墙钟超时强制杀掉，并按已消耗结算（不能白跑不计费，也不能跑一半全额计费）

## 5. 隔离断言（每个作业都要产出，不是一次性验收）

作业容器必须带全以下参数，**任一缺失即视为隔离未成立，不得执行**：

```
--rm  --network=none  --read-only  --cap-drop=ALL
--security-opt=no-new-privileges  --user <非 root>
--pids-limit=<上限>  --memory=<上限>  --cpus=<上限>
--tmpfs /tmp:rw,noexec,nosuid,size=<上限>
--mount type=bind,src=<输入>,dst=/src,ro=true
镜像：name@sha256:<64hex>
```

Runner 每个作业写一条隔离断言记录：实际生效的参数、镜像摘要、退出码、
资源峰值。这条记录是隔离证据的最小单元；**没有这条记录的作业结果不可用于交付**。

需要出网拉依赖的作业不能简单去掉 `--network=none`：走 `egress-proxy` 白名单，
并把实际访问过的域记入作业证据。

---

## 6. 产物回传

- Runner **不直接写业务数据库**，只把产物推到对象存储并回传摘要
- 回传内容：作业状态、退出码、日志摘要（脱敏）、产物 SHA-256、资源峰值
- 应用侧复算摘要后才对用户开放下载——这条既有实现已经在做，保持
- 按套餐保留期打标签，到期自动清理，清理动作写审计

## 8. 验收标准

| # | 验收点 | 证据 |
|---|---|---|
| 1 | 租户 A 的作业令牌无法执行租户 B 的作业 | 负向测试 |
| 2 | 过期令牌被拒绝；重放同一 `jti` 被拒绝 | 负向测试 |
| 3 | 可变镜像标签被拒绝，只接受 `@sha256:` | 负向测试 |
| 4 | 超过 `concurrentJobs` 的作业排队而非失败，且不跨租户饿死 | 并发测试 |
| 5 | 作业内尝试出网被拒绝（`--network=none` 真实生效） | 隔离测试 |
| 6 | 作业内尝试写只读根被拒绝 | 隔离测试 |
| 7 | 墙钟超时被杀死并按已消耗结算 | 故障注入 |
| 8 | Runner 主机上不存在业务数据库凭据 | 配置审计 |
| 9 | 每个作业都有隔离断言记录，缺失即拒绝交付 | 抽样核对 |

第 5、6 项是**真正的隔离证据**——它们能关闭 RISK-IDENTITY-001 的一部分，
但不能替代独立安全评审（RISK-SECURITY-001 仍需外部执行）。
