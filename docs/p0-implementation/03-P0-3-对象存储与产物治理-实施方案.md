## 1. 现状：声明了，但没接线

`deploy/compose/docker-compose.yml` 第 15 行确实起了 MinIO：

```yaml
minio:
  image: minio/minio:RELEASE.2025-07-23T15-54-02Z
  command: server /data --console-address :9001
```

但 `control-plane` 服务的环境变量里只有 `ELMOS_DATABASE_*`，根 `pom.xml` 里既没有 AWS SDK 也没有 MinIO 客户端。也就是说：**这一格是空的，不是半成品**。所有 ZIP、Evidence Pack、构建日志都还在产出它们的那个进程的本地磁盘上。

后果很直接：

- Web 起 2 个副本，用户在副本 A 生成、在副本 B 点下载 → **404**；
- 没有保留策略，磁盘只增不减，满了整站挂掉；
- 没有加密、没有跨区、没有「谁下载了客户的代码归档」的答案。

## 2. 设计要点

### 2.1 保留现有的正确部分

现有实现里有一件事做得很对，**必须原样保留**：产物是内容寻址的，且**浏览器会重新计算 SHA-256** 才接受下载（`BUSINESS_LINE_CLOSURE_MATRIX.md` 里明确记录）。

这条不变量是 presigned URL 能安全使用的前提——即使链接被中间人替换，浏览器也会因为摘要不符而拒收。所以 V54 只改「字节存在哪」，不改「怎么证明字节是对的」。

### 2.2 内容对象按租户隔离，不做全局去重

这是一个刻意的、会牺牲一点存储成本的决定。

全局按 digest 去重看起来很划算，但它会把制品库变成一个**跨租户存在性预言机**：租户 B 上传一个文件，如果系统秒回「已存在」，B 就知道租户 A 手里有一份字节完全相同的文件。对一个做代码迁移的平台来说，这等于泄露「谁在用哪个框架的哪个版本」。

所以唯一约束是 `UNIQUE (organization_id, content_sha256)`——同租户内去重，跨租户各存各的。

### 2.3 后端注册表默认 NOT_CONFIGURED

`object_storage_backends` 出厂就一行 `primary / S3 / NOT_CONFIGURED`。CHECK 约束保证：

- `LOCAL_FS` **永远无法**变成 ACTIVE；
- 变 ACTIVE 必须同时具备 endpoint、bucket、凭据引用、服务端加密（`SSE_KMS` 时还要 CMK 引用）、验证时间和具名验证人。

这是为了杜绝那个最常见的事故：「先临时用本地盘顶一下」，然后这个临时方案上了生产。烟测里验证了缺凭据时 ACTIVE 会被 CHECK 拒绝。

### 2.4 上传必须服务端验证摘要

```
Runner 计算 sha256 → 申请 presigned PUT → 直传 → 请求 verify
                                                    ↓
                                    服务端读回并复算 → 一致才 AVAILABLE
```

`elmos_publish_job_artifact()` 在对象不是 `AVAILABLE` 时直接抛 `ELMOS_CONTENT_OBJECT_NOT_VERIFIED`。**客户端声明的摘要永远不被信任**——这正是「截断的上传看起来像一个好归档」的防线。烟测覆盖了这条。

### 2.5 下载授权即审计

每发一个 presigned URL 就写一行 `artifact_download_grants`：谁、什么时候、哪个产物、什么时候过期、用了几次。**URL 和签名本身不入库**。

TTL 上限 15 分钟，写在 CHECK 里而不是代码里：

```sql
CONSTRAINT artifact_grant_max_ttl CHECK (expires_at <= issued_at + interval '15 minutes')
```

presigned URL 是不记名凭据，谁拿到谁能下。烟测验证了 2 小时的 grant 会被数据库拒绝。

### 2.6 保留策略复用套餐目录

`elmos_effective_retention_days()` 的优先级：

```
租户覆盖 (object_retention_policies)
  → 套餐目录 (self_service_pricing_plan_versions.artifact_retention_days)
    → 兜底 7 天
```

V49 里已经写好了：trial 7 天、pro-monthly 30 天、pro-annual 90 天。**不新建第二处配置**——改套餐即改保留期。烟测验证 pro-monthly 租户的产物到期日落在 30 天。

### 2.7 Legal Hold 压倒一切

`job_artifacts_legal_hold_not_expiring` CHECK 保证被冻结的产物不能带过期时间；`elmos_expire_artifacts()` 直接跳过 `legal_hold = true` 的行。烟测验证了 GC 不会删除被冻结的产物。

## 3. 存储布局

```
oss://elmos-artifacts/
  <organization_id>/                  ← 租户前缀，bucket policy 可独立强制隔离
    obj/<sha256>                      ← 内容寻址，不带文件名
```

文件名保存在 `job_artifacts.filename`，不进对象键。这样同一份字节被两个任务以不同文件名发布时不会产生两份存储。

租户前缀的意义在于：即使应用层有 bug，也可以在 bucket policy / RAM 策略层再加一道租户边界——**不依赖应用正确性的隔离**。

## 4. 迁移路径

### N1 · 应用 V54（零行为变化）

`primary` 后端是 NOT_CONFIGURED，没有任何代码在用它。

### N2 · 接入 SDK 与配置

- 根 `pom.xml` 加 `software.amazon.awssdk:s3`（阿里云 OSS 兼容 S3 协议，用同一个客户端 + 自定义 endpoint）；
- 实现 `S3ObjectStore implements ObjectStoragePort`；
- `deploy/compose` 里给 control-plane 补 `ELMOS_OBJECT_STORAGE_*`，本地开发指向已有的 MinIO。

### N3 · 双写（一个发布周期）

新产物同时写本地盘和对象存储，下载仍走本地。用于验证上传、校验、签名链路，不影响用户。

### N4 · 下载切到 presigned

`ts/jobClient.ts::artifactDownloadTicket()` 替换现有的字节转发。前端只改「拿 URL」这一步，**SHA-256 复算逻辑一行不动**。

### N5 · 回迁历史产物

对本地盘上仍在保留期内的产物做一次性上传与登记；超期的直接按保留策略处理（并留下 GC 记录）。

### N6 · 关闭本地写

删除本地产物路径。此时 Web 与 Runner 都不再需要持久卷。

## 5. 验收标准

数据库层已验证：

- [x] 缺凭据/缺加密时后端无法变 ACTIVE
- [x] `LOCAL_FS` 永远无法变 ACTIVE
- [x] 未经服务端校验的对象无法发布
- [x] 保留期来自套餐目录（pro-monthly → 30 天）
- [x] 超过 15 分钟的下载授权被拒
- [x] 下载授权全部留痕
- [x] Legal Hold 的产物不会被 GC 删除

端到端还需要：

- [ ] Web 起 3 副本，任一副本签发的链接均可下载且摘要一致
- [ ] 篡改对象 1 字节后，浏览器端复算失败并拒绝交付
- [ ] 保留策略在测试租户上真实到期、真实删除、留下 `object_gc_runs` 证据
- [ ] 跨区复制配置生效（对应 P1-10 的 DR 要求）
- [ ] 租户数据导出：一次请求拿到该租户全部在留产物的清单与下载授权
