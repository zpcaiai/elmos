## 3. 任务 ③ 代码实现:16 个原型实现一次,驱动全部 44 个 batch

16 个原型在 44 个 batch 里是同一套。实现一次 = 真正驱动全部 44 个。

| 模块 | 实现的能力 |
|---|---|
| `canonical.py` | 规范化 JSON、内容寻址、稳定排序、幂等键;**拒绝 float 和 set**(它们没有确定性表示) |
| `validation.py` | 信任边界 Draft 2020-12 校验;内置校验器**比库更严**——遇到它不认识的关键字直接报错,而不是静默忽略 |
| `packages.py` | 加载并逐字节校验 44 个包 |
| `policy.py` | 默认拒绝、租户隔离、Agent 边界、审计记录 |
| `evidence.py` | 证据存储(digest 是算出来的,不接受调用方声明)、过期、血缘图、双跑对账 |
| `certification.py` | 保守认证 Gate、状态格 |
| `engine.py` | 确定性引擎:可重放、Worker 数无关、有界 |
| `workflow.py` | 持久化工作流:Lease、精确一次事件、补偿回滚 |
| `approval.py` | 审批绑定到请求 digest、双人控制 |
| `adapters.py` | Provider 版本钉死与漂移检测 |
| `corpus.py` | 四类语料 + 显式分母 + 预算 |
| `orchestrator.py` | 单 batch 端到端 + B01→B44 链式执行 |

**策略文件是可执行的,不是装饰**:`certification.yaml` 里把 `holdout_required_for_certified` 改成 false,Gate 的判定**真的会变**——这一点由 M06 变异实验证明。

实测:B01→B44 完整链路跑通,44 张证书、264 条证据、44 个工作流,**同样输入两次运行 digest 完全一致**。

## 4. 验证:803 个真实用例 + 20/20 变异全部杀死

### 4.1 用例构成

- **528 个契约用例**:44 batch × 12 条声明义务,每条都真的驱动运行时,并断言**具体的拒绝原因**(不是"抛了个异常就算过")
- **275 个补充用例**:16 个原型的单元测试、包完整性、全链路 E2E、堵住变异发现的漏洞

### 4.2 为什么这些测试是"真的"——变异测试

`mutation_check.py` 逐条删掉运行时里的强制规则,要求测试必须变红:

**第一轮:15/20 杀死,5 个存活**——这 5 个是真漏洞:

| 存活变异 | 暴露的问题 | 修复 |
|---|---|---|
| M04 | 空证书列表这条路径没有任何测试覆盖 | 直接在 Gate 层加断言 |
| M06 | `holdout_required` 策略位是**冗余的**,删了行为不变 | 重构:策略位真正决定 `required_evidence`,策略文件从此有效 |
| M13 | output digest 比较被 journal digest 比较遮蔽 | 断言异常信息必须指明是 output digest |
| M19 | 没有任何测试篡改过包文件 | 加"复制包→改一个字节→必须报 digest mismatch" |
| M20 | 内置校验器被 jsonschema 遮蔽,从未被执行 | 显式关掉 jsonschema 测内置路径,并断言两个校验器结论一致 |

**第二轮:20/20 全部杀死。**

## 5. 顺带修掉的两个仓库真实缺陷

1. **`validate_skill_bundle.py` 硬编码 `assert len(files)==32`** —— bundle 长到 42 个后必然失败,且不告诉你哪个 Skill 有问题。改为以 registry 为准校验,报出具体文件;并接受扩展 Skill 使用的中文小节标题(`实施流程`/`验证`/`停止与升级`/`完成定义`)。

2. **`FILE_MANIFEST.json` 里混进了 `__pycache__/test_toolkit.cpython-313.pyc`** —— 把整个包钉死在 Python 3.13 上,换任何版本必失败。从三个 manifest 里清掉,并在导入器里加硬拒绝,防止再次混入。

## 7. 这份工作**没有**声称什么

- 运行这套运行时只会签发 `limited` 证书,因为跑的语料是合成的。`certified` 还需要 `independent-review` 证据——按定义,产出物不能由产出它的同一个进程来独立复核。
- **未实现**:B19 的 72 条语言转换路线、B28 的 12 条数据库方言映射、真实的 Java/C#/Python 解析器与代码生成器。这些是**领域内容**,不是这 16 个原型;它们需要逐条实现和逐条取证。本次交付的是**能承载它们、并且会在它们造假时拒绝签发证书的执行与认证骨架**。
- 那 5 个 `spec-only` 系列(b1-55、b40-55、b81-95、b97-104、platform-b1-38,合计 2,939 个 Skill 文件)**仍然没有实现**。审计脚本会持续如实报告。
- JVM 侧 843 个 Java 文件本次**未编译、未测试**。
