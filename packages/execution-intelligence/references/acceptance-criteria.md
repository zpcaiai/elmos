# 验收标准

## 估算部分

- [ ] 分类 token 互斥，`total` 等于分类之和，逐样本可断言
- [ ] 每个任务的 token 可独立追溯到分位数
- [ ] 系统 ETA 的 `excludes` 明文列出人工审批、验收、凭据等待
- [ ] 人工基线与系统估算共用同一份 DAG，`same_definition_of_done` 为真
- [ ] 每个输出带 `assumptions`、`exclusions`、`confidence`
- [ ] 费率缺 `effective_date` / `verified_at` / `source_reference` 时校验拒绝
- [ ] 不同币种不出现在同一个排名里
- [ ] 每个 JSON 产物在写盘后被 schema 校验，失败即 BLOCKED

## 持久执行部分

- [ ] 客户端断开后运行继续，重连后状态、事件、结果都补齐
- [ ] 事件序号单调、无空洞，`Last-Event-ID` 重放不丢不重
- [ ] 同一幂等键重复请求返回原响应，副作用只发生一次
- [ ] 同一幂等键配不同请求体返回冲突，而不是旧响应
- [ ] Worker 丢失后先核对请求 / Commit / Artifact，再决定重试
- [ ] 从 Checkpoint 恢复后不重复已完成的任务
- [ ] Artifact 内容寻址，相同字节重复发布是幂等的

## 认证部分

- [ ] 每条门禁都有可执行证据，没有证据的门禁记为未通过而不是跳过
- [ ] Chaos 场景清单覆盖 Worker 丢失、编排器重启、客户端断连、重复提交
- [ ] 报告里区分"已执行并通过"和"未执行"，不允许用未执行冒充通过

## 不算通过的情况

- 用示例费率给出的费用当成预算承诺
- 用未校准的预测当成交付承诺
- 把 schema 写好但从未执行
- 把"测试存在"当成"测试通过"
