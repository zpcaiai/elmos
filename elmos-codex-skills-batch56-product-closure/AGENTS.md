# ELMOS Batch 56 — Product Closure and Consolidation Rules

## Mission
Convert the Batch 1–55 capability estate from a broad Skill catalog into a coherent, runnable, certifiable, commercially deliverable Enterprise Modernization Operating System.

## Global rules
1. Do not add new horizontal capability batches while closure gates are open.
2. Prefer canonical shared objects over batch-local duplicates.
3. Every capability claim must have a maturity state and evidence reference.
4. Static package validity is not runtime certification.
5. Golden journeys, provider adapters, execution reliability, security, evidence, upgrades and customer acceptance are first-class release requirements.
6. Planning-edition Skills cannot be promoted directly to GA.
7. Every side effect requires idempotency, reconciliation and compensation semantics.
8. Every public or customer-facing capability must map to a supported product edition and support policy.
9. Core platform logic must not depend directly on provider DTOs.
10. Final certification requires immutable runtime evidence from representative workloads.
